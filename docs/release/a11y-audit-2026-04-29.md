### Why the raw count is much higher than true positives

The 57 raw button hits decompose to:
- **26 × `<Loader2/>`** — loading spinners inside ternaries like `{loading ? <Loader2/> : "Save"}`. The button has visible text ("Save"); the spinner only appears mid-action and its parent button retains its accessible name. ✓ False positive.
- **5 × `<ChevronUp/>` collapsible-trigger toggles** — true positives, fixed (see below).
- **6 × icon-with-sibling-text inside fragment** — e.g. `<><Upload/> Upload Document</>` or `<><Send className="ml-2"/> </>` after "Send Message". The button has accessible text; my regex couldn't see across the JSX fragment. ✓ False positive (manually verified each).
- **20 × oversize button findings dropped** by the iconName+text heuristic.

## Uncertain — needs human review (NOT modified)

### Inputs without explicit `id` / `Label htmlFor`

Raw counts:
- `<Input>` total: 725
- `<Input id="…">`: 7
- `<Textarea>` total: 105
- `<Textarea id="…">`: 1
- `<Label htmlFor="…">`: 188

This *looks* alarming but is largely a shadcn-`<FormField>` convention: `FormField` + `FormLabel` + `FormControl` auto-wires `htmlFor`/`id` via React context (the rendered DOM has the association even though the source code doesn't show explicit `id=`). A spot-check of `src/components/onboarding/OnboardingWizard.tsx`, `WizardSystem`, and the property edit forms confirms `FormField` is the dominant pattern.

**Risk of mass-fixing**: adding manual `id=` to inputs already inside `FormField` would either be a no-op or cause double-binding bugs. **Action**: defer to a per-form manual audit (best done with axe-core against the running app) — the cases that *aren't* inside `FormField` need tracing one form at a time. That is out of scope for a mechanical pass.

### Form-search inputs in headers / toolbars

Many search `<Input>`s sit in toolbars without a visible `<Label>`. They use `placeholder="Search…"` only. WCAG-AA-compliant fix is to add `aria-label="Search …"`. Listed for the next pass — flagged but not modified to avoid touching dozens of files without UX confirmation of the wording.
